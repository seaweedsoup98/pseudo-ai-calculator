# pseudo-ai-calculator

* Python으로 MAC(Multiply-Accumulate) 연산을 직접 구현한 Mini NPU 시뮬레이터
* 3×3 사용자 입력과 `data.json` 기반 5×5, 13×13, 25×25 패턴 판별 지원
* 외부 라이브러리 없이 Python 표준 라이브러리만 사용

## 실행 방법

```bash
python3 main.py
```

* `1`: 사용자 입력 모드
* `2`: `data/data.json` 분석 모드

## 구현 요약

* MAC 연산

  * 패턴과 필터의 같은 위치 값을 곱한 뒤 순서대로 누적
  * N×N 입력에서 총 N²번의 MAC 연산 수행
* 입력 검증

  * 3×3 입력에서 행별 숫자 개수와 숫자 변환 여부 검사
  * 잘못된 입력은 오류 안내 후 재입력
* 라벨 정규화

  * expected `+` → `Cross`
  * expected/filter `x` → `X`
  * filter `cross` → `Cross`
* 점수 비교

  * `epsilon = 1e-9`
  * 두 점수 차이가 epsilon보다 작으면 동점 처리
  * 모드 1: `판정 불가`
  * 모드 2: `UNDECIDED`
* JSON 분석

  * `size_{N}_{idx}` 키에서 N을 추출
  * 해당 크기의 `size_N` 필터 선택
  * 패턴/필터 크기 또는 스키마 오류는 케이스 단위 FAIL 처리
* 성능 측정

  * `time.perf_counter()`로 MAC 함수 호출 구간만 측정
  * 크기별 10회 측정 후 평균 시간 출력

## 실행 결과

### 모드 1

* Cross 필터와 X 필터에 X 패턴 입력
* A 점수: `1.0`
* B 점수: `5.0`
* 판정: `B`
* 잘못된 열 개수 입력 시 오류 안내 후 정상적으로 재입력됨
* `0.9`와 `0.8999999999999999` 비교 시 epsilon 정책에 따라 `판정 불가` 처리됨

### 모드 2

* 전체 테스트: `6`
* 통과: `3`
* 실패: `3`

| 케이스       |          Cross 점수 |               X 점수 | 판정        | expected | 결과   |
| --------- | ----------------: | -----------------: | --------- | -------- | ---- |
| size_5_1  |               0.9 | 0.8999999999999999 | UNDECIDED | X        | FAIL |
| size_5_2  |               8.9 |                0.1 | Cross     | Cross    | PASS |
| size_13_1 |               0.3 | 14.700000000000008 | X         | X        | PASS |
| size_13_2 | 7.499999999999997 |                7.5 | UNDECIDED | Cross    | FAIL |
| size_25_1 |               4.9 |  4.899999999999999 | UNDECIDED | X        | FAIL |
| size_25_2 |              52.9 |                0.1 | Cross     | Cross    | PASS |

## 성능 분석

공용 Mac에서 각 크기별 MAC 연산을 10회 수행한 평균값이다.

| 크기    | 평균 시간(ms) | 연산 횟수(N²) |
| ----- | --------: | --------: |
| 3×3   |  0.002360 |         9 |
| 5×5   |  0.004700 |        25 |
| 13×13 |  0.023982 |       169 |
| 25×25 |  0.079162 |       625 |

## 결과 리포트

* `data.json`의 6개 케이스 중 3개가 PASS, 3개가 FAIL로 판정되었다.
* `size_5_1`, `size_13_2`, `size_25_1`은 두 MAC 점수의 차이가 `1e-9`보다 작아 `UNDECIDED`가 되었다.
* 세 FAIL은 스키마나 MAC 구현 오류가 아니라 명시된 epsilon 동점 정책에 따른 결과이다.
* `size_5_1`의 `0.9`와 `0.8999999999999999`처럼 부동소수점은 수학적으로 같은 값도 미세한 차이를 가질 수 있다.
* 이러한 미세 차이를 단순한 `>` 비교로 판정하면 실행 결과가 의도와 다르게 결정될 수 있어 epsilon 비교가 필요하다.
* expected의 `+`, `x`와 필터의 `cross`, `x`는 각각 `Cross`, `X`로 정규화한 뒤 비교한다.
* 라벨 정규화로 외부 데이터의 표현 방식과 프로그램 내부의 판정 기준을 분리할 수 있다.
* N×N MAC에서는 모든 위치를 한 번씩 방문하므로 연산 횟수는 N²이다.
* 실제 연산 횟수도 9, 25, 169, 625로 패턴 크기의 제곱에 따라 증가한다.
* 측정 결과에서도 크기가 커질수록 평균 실행 시간이 증가하는 경향을 확인할 수 있다.
* 따라서 MAC 함수의 시간 복잡도는 `O(N²)`로 설명할 수 있다.
* 측정 시간 자체는 CPU 상태와 실행 환경의 영향을 받으므로 실행할 때마다 소폭 달라질 수 있다.
* 시간 측정에는 파일 읽기와 콘솔 출력 시간을 포함하지 않고 MAC 연산 함수 호출 구간만 포함했다.

## 보너스 구현

### 1차원 배열 최적화

* N×N 행렬을 길이 N²의 1차원 배열로 변환
* 동일한 입력을 2차원 MAC과 1차원 MAC에 적용하여 성능 비교
* flatten 변환 시간은 측정에서 제외

| 크기    | 최적화 전(ms) | 최적화 후(ms) |
| ----- | --------: | --------: |
| 3×3   |  0.002360 |  0.001130 |
| 5×5   |  0.004700 |  0.002372 |
| 13×13 |  0.023982 |  0.012902 |
| 25×25 |  0.079162 |  0.045535 |

* 이번 실행에서는 모든 크기에서 1차원 접근 방식의 평균 시간이 더 짧게 측정되었다.

### 패턴 생성기

* 입력 크기 N에 대해 Cross와 X 패턴을 자동 생성
* 모드 1에서 직접 입력 대신 자동 생성된 3×3 패턴 사용 가능
* 성능 분석에서도 같은 생성기를 사용하여 테스트 데이터 생성

```text
X 3×3 예시

1.0 0.0 1.0
0.0 1.0 0.0
1.0 0.0 1.0
```
